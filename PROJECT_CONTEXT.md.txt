## 7. Current Problems and Areas for Improvement

### A. Inconsistent UI

Previous development involved many incremental CSS changes, resulting in possible duplicate rules, inconsistent component styling, and layout issues.

Review the full stylesheet hierarchy and consolidate the design.

The target is a cohesive interface, not simply the old interface with different colors.

### B. Desktop responsiveness

The latest screenshot showed an overly wide remote panel, excessive spacing, and an interface that did not look sufficiently polished on desktop.

Create sensible responsive layouts for both iPhone Safari and desktop browsers.

The desktop version should not be an oversized mobile layout.

### C. Missing status information

The latest screenshot showed:

- Power: —
- Volume: —
- Active App: —

Investigate whether the backend was disconnected, the frontend was failing to fetch status, or the new UI introduced a JavaScript problem.

Do not fabricate values.

Distinguish disconnected, unavailable, and loading states appropriately.

### D. Live volume reporting

The Android TV Remote Protocol library exposes a `VolumeInfo` structure containing:

- `level`
- `max`
- `muted`

The application previously registered a volume update callback, but the frontend often displayed no volume information.

Investigate callback registration, initial state hydration, reconnection behavior, and backend status serialization.

If ADB can provide a reliable fallback, consider it carefully.

Display real values only. Do not invent volume percentages.

### E. Installed app discovery

The backend previously had a hardcoded app list, including Plex, YouTube, Spotify, and Netflix.

The user wants the app launcher to show applications genuinely installed on the television.

ADB is available and authorized.

Implement reliable installed-app discovery with friendly names where possible, graceful failure handling, and a safe allowlisted launch mechanism.

Never expose arbitrary ADB shell execution to unauthenticated browser requests.

### F. Favorites

Verify that favorite apps are saved per television, displayed on the Remote tab, and can be reordered without losing state.

### G. Device diagnostics

The app already has a TV hardware endpoint:

`/api/device-info/<tv_id>`

It previously returned:

- Model and Android version
- RAM usage and availability
- Internal storage usage and availability

The More tab displays RAM and storage usage bars.

Preserve this functionality and improve its visual presentation.

Previously observed values were approximately 2 GiB RAM and 10 GiB internal storage. These are historical observations, not values to hardcode.

### H. Touchpad and interaction quality

Improve touch feedback, gesture responsiveness, button states, and accessibility.

Respect reduced-motion settings.

Ensure long-press power continues to work correctly.

### I. Development workflow

Eliminate the need for manually changing CSS version query parameters or repeatedly editing CSS over SSH.

Establish a proper local development and deployment workflow with:

- Git
- Sensible project structure
- Automated checks
- Safe configuration management
- Build or deployment scripts where useful
- Backup and rollback support

Do not introduce unnecessary frameworks or complexity.
